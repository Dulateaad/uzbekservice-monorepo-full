# ТЕХНИЧЕСКОЕ ЗАДАНИЕ. Расширение браузера: сканирование карточек товаров (одежда) на маркетплейсах и выгрузка в Excel

**Версия:** 1.0 | **Статус:** к согласованию

---

## 1. Назначение

Разработать **расширение для браузера** (Chrome / Edge на базе Chromium; опционально Firefox), которое на **странице карточки товара** маркетплейса одежды **извлекает** структурированные данные (ссылки на изображения, текстовое описание, цену, артикул и т.д.) и **сохраняет** их в файл формата **Excel** (.xlsx) для дальнейшего анализа, каталогизации или интеграции с внешними системами.

**Целевая аудитория:** пользователь (мерчендайзер, аналитик, продавец), работающий с публичными страницами товаров вручную или пакетно.

---

## 2. Цели и задачи

| Цель | Критерий успеха |
|------|-----------------|
| Сбор данных с одной открытой страницы | Одно нажатие действия → строка(и) в таблице с заполненными полями по правилам разд. 4 |
| Выгрузка в Excel | Файл .xlsx открывается в Microsoft Excel / LibreOffice без ошибок; кодировка UTF-8 для текста |
| Прозрачность источника | В каждой записи сохраняется **URL страницы**, с которой сняты данные |
| Ограничение ответственности | Расширение не обходит авторизацию и не нарушает условия использования площадки (разд. 10) |

---

## 3. Область применения и приоритеты площадок

**3.1. MVP (обязательно согласовать список с заказчиком):**

- Не менее **одной** площадки из перечня (пример): Wildberries, Ozon, Lamoda, локальный маркетплейс — **конкретные домены** фиксируются в приложении к ТЗ.
- Для каждой площадки — отдельный **адаптер** (селекторы / JSON-LD / микроразметка), т.к. вёрстка и API страницы различаются.

**3.2. Релиз 1.x (бэклог):**

- Дополнительные площадки по тому же контракту данных (разд. 4).
- Пакетный режим: обход списка URL из буфера/файла — **только** если не противоречит политике площадки и закону (разд. 10).

---

## 4. Состав собираемых данных (минимальный набор)

Поля задаются заказчиком; **рекомендуемый** минимум для карточки одежды:

| Поле | Описание | Обязательность |
|------|-----------|----------------|
| `source_url` | Полный URL страницы карточки | Обязательно |
| `title` | Название товара | Обязательно |
| `description` | Описание (основной текст; при нескольких блоках — конкатенация с разделителем или отдельные колонки — согласовать) | Желательно |
| `price_current` | Текущая цена (число + валюта в отдельной колонке или ISO) | Желательно |
| `price_old` | Зачёркнутая / «до скидки» | Опционально |
| `currency` | Код валюты | Опционально |
| `brand` | Бренд | Опционально |
| `sku` / `article` | Артикул / SKU на площадке | Опционально |
| `size_grid` | Доступные размеры (текст или JSON-строка в ячейке) | Опционально |
| `image_urls` | Все URL изображений товара (галерея): **одна колонка** с разделителем `;` **или** несколько колонок `image_1`…`image_N` — **выбрать один вариант** в ТЗ | Обязательно (минимум главное фото) |
| `category_path` | Хлебные крошки / категория | Опционально |
| `scraped_at` | Дата и время сбора (ISO 8601, часовой пояс пользователя) | Обязательно |

**Дополнительно по согласованию:** рейтинг, количество отзывов, состав ткани, страна производства, ссылка на продавца.

## 5. Функциональные требования

**5.1. Интерфейс расширения**

- Иконка на панели инструментов браузера.
- Всплывающее окно (popup) или боковая панель с кнопками:
  - **«Собрать с этой вкладки»** — парсинг активной вкладки (только если URL входит в whitelist доменов MVP).
  - **«Экспорт в Excel»** — формирование и скачивание .xlsx из накопленного буфера сессии.
  - **«Очистить буфер»** — сброс накопленных строк до экспорта.
- Индикация: успех / ошибка (нет адаптера для домена, таймаут, изменилась вёрстка).

**5.2. Логика сбора**

- Контент страницы читается через **content script** после загрузки DOM; при динамической подгрузке — ожидание появления ключевых элементов (таймаут и лимит попыток — указать в реализации, напр. 10–15 с).
- Приоритет источников данных (рекомендация): **JSON-LD** (`Product`) → **Open Graph** meta → **DOM-селекторы** по стабильным атрибутам/data-* (хрупкие классы — избегать или версионировать адаптер).
- Изображения: абсолютные URL; миниатюры заменять на полноразмерные по правилам конкретной площадки (если известны).

**5.3. Excel**

- Формат: **Office Open XML** (.xlsx), одна книга, лист по умолчанию `Items` (или имя из ТЗ).
- Первая строка — **заголовки** колонок (как в разд. 4).
- Каждое нажатие «Собрать» добавляет **одну строку** на товар; если на странице несколько вариантов (например, сводная витрина) — поведение **«одна строка на URL»** или **«несколько строк»** — зафиксировать в приложении к ТЗ.
- Ограничение длины ячейки Excel (32 767 символов): длинное описание **обрезать** с пометкой в конце `[…]` или выносить в отдельный текстовый файл — выбрать в ТЗ.

**5.4. Хранение до экспорта**

- Вариант A: только **память** сессии (очистка при закрытии браузера).
- Вариант B: **chrome.storage.local** с лимитом записей (напр. до 500 строк) — согласовать с заказчиком.

**5.5. Архитектура: нужен ли бэкенд**

| Режим | Описание | Когда достаточно |
|--------|----------|------------------|
| **Только клиент (MVP по умолчанию)** | Content script парсит DOM → данные в памяти / `chrome.storage` → сборка .xlsx в расширении (библиотека SheetJS или аналог) → скачивание файла пользователю. **Сервер не используется.** | Один пользователь, ручной сбор, нет синхронизации между устройствами |
| **Опциональный бэкенд (релиз 1.x+)** | Расширение по явной кнопке отправляет JSON на **ваш** API (HTTPS); сервер пишет в БД, S3, шлёт в очередь, отдаёт готовый Excel по ссылке | Общий каталог команды, история, интеграция с CRM/1С, тяжёлая отчётность на сервере |

**Если бэкенд вводится**, типовой контур (на выбор ИТ):

- **HTTP API:** `POST /api/items` — тело: массив записей в контракте разд. 4; ответ: `{ "ok": true, "id": "..." }` или presigned URL на .xlsx.
- **Аутентификация:** API-ключ в заголовке, JWT после логина, или Firebase Auth — зафиксировать в приложении к ТЗ; **без** передачи cookies маркетплейса на бэкенд.
- **Стек (пример, не норма):** Node (Express/Fastify), Python (FastAPI), Go; БД PostgreSQL или облако (Firestore, Supabase); файлы — объектное хранилище при необходимости.
- **Не делать:** прокси-скрейп с сервера IP датацентра по маркетплейсам без отдельного юр/технического ТЗ (блокировки, ToS).

**Итог для MVP:** бэкенд **не обязателен**; расширение — полноценное приложение в браузере. Бэкенд добавляется, когда появляются требования к **мультипользовательскому хранению**, **очередям**, **серверной выгрузке** или **интеграциям**.

## 7. Права расширения (permissions)

- `activeTab` + **host_permissions** только для **согласованных** доменов маркетплейсов (минимальный принцип).
- Без доступа ко всем сайтам (`<all_urls>`), если нет отдельного обоснования и согласования ИБ.
- Сетевые запросы: для MVP **к своему бэкенду не требуются**; при появлении API — **host_permissions** только на домен бэкенда + маркетплейсы из whitelist.

---

## 8. Безопасность и соответствие

- Не хранить и не передавать **логины/пароли** пользователя площадки третьим лицам.
- Не внедрять скрытую отправку собранных данных на внешний сервер без **явного** согласия пользователя и описания в политике расширения (для MVP — **только локальная** выгрузка файла).
- Соблюдение **ToS** маркетплейса и применимого законодательства (автоматизированный массовый парсинг может быть запрещён — ответственность на стороне заказчика/пользователя; разд. 10).

---

## 9. Критерии приёмки (пример)

1. На **согласованной** тестовой карточке (3–5 фиксированных URL от заказчика) после «Собрать» в буфере появляется запись с заполненными `source_url`, `title`, минимум одним `image_url`, `scraped_at`.
2. «Экспорт в Excel» выдаёт файл, который открывается в Excel 2019+ / Google Sheets (импорт) с корректной кириллицей.
3. На домене **вне** whitelist — понятное сообщение «Площадка не поддерживается».
4. При отсутствии поля на странице — ячейка пустая или `N/A` (единое правило по всему файлу).

---

## 10. Ограничения и риски (зафиксировать для заказчика)

- Вёрстка и DOM маркетплейсов **меняются** без предупреждения — потребуется сопровождение адаптеров.
- **Robots.txt / Terms of Service** могут ограничивать автоматический сбор; массовый скрейп и обход капчи **вне scope** данного ТЗ.
- Юридическая чистота использования изображений и текстов описаний при коммерческом повторном использовании — **не входит** в техническую реализацию расширения; консультация юриста — на стороне заказчика.
