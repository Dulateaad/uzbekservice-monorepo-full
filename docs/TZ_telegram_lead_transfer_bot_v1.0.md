# ТЗ: Telegram-бот «Lead Transfer Bot Auto» (передача лидов, авто)

Версия: 1.0  
Назначение: менеджеры, АТЗ, руководители (РОП) — учёт, передача лидов, сроки, аналитика.

---

## 1. Стартовое меню (ролевая логика)

После `/start` бот определяет **роль** сотрудника (мэппинг: Telegram `user_id` / телефон → Firestore/БД) и показывает соответствующее **главное меню** (inline-кнопки).

## 5. Регистрация клиента (АТЗ) — сценарий

**Старт:** `👤 Зарегистрировать клиента`

### Шаги (последовательно)

1. **ФИО** — свободный ввод.  
2. **Телефон** — валидация формата (KZ +7, маска по необходимости).  
3. **Бренд (интерес)** — **inline-кнопки** (один выбор):

   OMODA · JAECOO · LADA · GAC · Changan · JAC · Chery · Jetour · **Б/У**

4. **Форма оплаты** — кнопки:  
   💳 Кредит · 💵 Наличные · 🔁 Trade-in

5. **Бюджет** — число/диапазон (уточнить: свободный ввод в млн тг).

### Подтверждение

Сводка: ФИО, Телефон, Бренд, Бюджет (+ при необходимости способ оплаты).

**Вопрос:** «Передать менеджеру?»

- ✅ Да → создание `Lead` в статусе, назначение/очередь менеджера (правило: round-robin / по бренду / ручной выбор в MVP-обсуждении).  
- ❌ Нет → сохранить как черновик или отмена (определить в бизнес-логике).

---

## 6. Передача клиента (менеджер)

**Старт:** `🔄 Передать клиента`

1. **Выбор клиента** — список **лидов менеджера** (короткие карточки: ФИО + бренд + статус).  
2. **Причина передачи** (одна):

   💰 Высокая цена  
   🚫 Нет наличия  
   ❌ Не понравился бренд  
   📉 Не прошёл кредит  
   🔁 Хочет обмен  
   🚗 Нужен Б/У  

3. **Куда передать:**

   Другой бренд · Б/У · Выкуп · Финансовый отдел

4. **Комментарий** — свободный текст (пример: «нужен кроссовер до 14 млн»).

5. **Результат:** «Клиент передан» + уведомление **получающему** (см. п. 7) + лог в `transfers` / `lead_events`.

---

## 7. Получение лидa другим отделом (уведомление)

**Push в чат ответственного / очереди отдела:**

```
🔔 Новый лид
Клиент: {ФИО}
Телефон: {телефон}
Интерес: {бренд}
Комментарий: {текст}
```

**Действия (inline):**

- ✅ Принять  
- 📞 Связался (фиксация времени, сброс SLA-таймера)  
- 📅 Назначил встречу  
- ❌ Отказ (с обязательной причиной из справочника или ввод)

---

## 8. Таймеры и SLA (контроль времени)

| Условие | Действие |
|--------|----------|
| **15 минут** после появления лида — нет нажатия **📞 Связался** | Сообщение лид-менеджеру: «⏰ Напоминание: обработайте клиента» |
| **30 минут** — всё ещё нет «Связался** | **РОП** получает: `⚠️ Просроченный лид` + менеджер, клиент, время ожидания |

(Таймеры хранить на сервере: Cloud Functions + scheduled task / Firestore `scheduled_at` + воркер, не только в памяти бота.)

## 9. «Мои лиды» (менеджер)

**Старт:** `📋 Мои лиды`

Список: нумеровано, кратко: `Фамилия — статус` (Новый / Встреча / Передан / …).

**По клику на лид** — **карточка:** ФИО, телефон, интерес, статус, комментарий.

**Кнопки:**  
✏️ Изменить статус · 🔄 Передать (см. п. 6) · 📝 Добавить заметку

## 10. Статистика менеджера

**Старт:** `📊 Моя статистика`

**За период (по умолчанию месяц, переключатель в настройках — позже):**

- Новых  
- Передано  
- Продано (или «закрыто+»)  
- Конверсия %  

---

## 11. Статистика руководителя (РОП)

**Старт:** `📊 Статистика`

**Сводка (пример, «Сегодня»):**

- Новых клиентов  
- Передано  
- Закрыто  
- Потеряно  
- Среднее время ответа (после «Связался» или с момента лида)  

**Доп. срезы (кнопки):**

- По брендам  
- По менеджерам  
- По причинам отказов (см. п. 12)

## 12. Причины отказов (топ, РОП)

Пример отчёта:

1. Высокая цена — 34%  
2. Нет наличия — 22%  
3. Кредит — 18%  
4. Передумал — 14%  

(Агрегация из полей `lost_reason` по закрытым/потерянным лидам.)

---

## 16. Сквозная бизнес-логика (сжато)

**Цепочка (идея):**  
АТЗ → (бренд, оплата) → **Lead** → при необходимости «Передать» → **другой отдел / бренд** → сделка / отказ

**События для аналитики:** `created`, `transferred`, `status_changed`, `first_contact` (связался), `meeting_set`, `lost` (с причиной), `won`.

---

## 17. Ценность для руководства (дашборды/бот)

- Скорость обработки (SLA)  
- Потерянные / передаваемые лиды  
- Нагрузка и конверсия по менеджерам  
- «Узкие» отделы (много просрочек / отказов)  
- Куда «утекает» воронка (деньги / лиды)

## 18. MVP (первый запуск)

Минимум:

1. Регистрация клиента (АТЗ) — п. 5  
2. Передача клиента (менеджер) — п. 6  
3. Уведомления получателям — п. 7  
4. Контроль 15/30 мин — п. 8 (серверные таймеры)  
5. Статистика: хотя бы «сегодня/неделя» — п. 10–11 (упрощённо)  

**Отложить:** AI-рекомендации, сложные дашборды, полная админка в боте.

## 20. Технические рекомендации (кратко)

- **Stack:** `node-telegram-bot-api` / **Telegraf** (Node) или Python **aiogram**; backend — **Firebase** (как в других ТЗ) или существующий API.  
- **Данные:** сущности `User` (роль, tg_id), `Lead`, `LeadEvent`, `Transfer`, `Settings` (SLA минуты).  
- **Надёжность:** idempotent обработка callback, очереди для напоминаний (Cloud Scheduler + Pub/Sub).  
- **Безопасность:** не хранить лишние PII в логах; доступ к РОП по роли.
