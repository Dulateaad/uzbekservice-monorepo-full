# 🔐 Варианты аутентификации в ODO.UZ

## ✅ Реализованные методы

### 1. 📱 SMS-аутентификация (Firebase Phone Auth)
**Статус:** ✅ Полностью реализовано  
**Для кого:** Клиенты, специалисты (опционально)

**Как работает:**
- Пользователь вводит номер телефона
- Получает SMS с кодом подтверждения
- Вводит код для завершения входа
- Использует reCAPTCHA v2 для защиты от ботов

**Особенности:**
- Поддержка номеров Узбекистана (+998) и Казахстана (+7)
- Автоматическое форматирование номера
- Тестовые номера для разработки (без reCAPTCHA)
- Автоматическое создание пользователя в Firestore

**Файлы:**
- `lib/screens/auth/beautiful_login_screen.dart`
- `lib/screens/auth/sms_verification_screen.dart`
- `lib/services/firebase_auth_service.dart`

---

### 2. 🆔 OneID аутентификация
**Статус:** ✅ Полностью реализовано  
**Для кого:** Специалисты (рекомендуется), клиенты (опционально)

**Как работает:**
- Пользователь нажимает "Войти через OneID"
- Открывается браузер с формой авторизации OneID
- После успешной авторизации возвращается в приложение
- Автоматически создается/обновляется профиль в Firestore

**Преимущества:**
- ✅ Безопасная государственная система идентификации
- ✅ Автоматическая верификация пользователя
- ✅ Получение данных из государственной базы (ФИО, ПИНФЛ, email, телефон)
- ✅ Не требует SMS кода

**Интеграция:**
- Backend: Firebase Functions (`oneidLogin`, `oneidCallback`, `oneidUser`)
- OAuth2 flow с redirect через HTTPS
- Deep linking для мобильных приложений

**Файлы:**
- `lib/screens/auth/oneid_auth_screen.dart`
- `lib/screens/auth/specialist_oneid_login_screen.dart`
- `lib/services/oneid_service.dart`
- `lib/config/oneid_config.dart`

## 💡 Текущая архитектура

### Провайдеры:
- `FirestoreAuthProvider` - основной провайдер аутентификации
- `AuthProvider` - устаревший, используется для совместимости

### Сервисы:
- `FirebaseAuthService` - работа с Firebase Phone Auth
- `OneIdService` - интеграция с OneID
- `FirestoreService` - работа с пользователями в Firestore

### Поток аутентификации:
1. Пользователь выбирает метод входа
2. Проходит аутентификацию (SMS/OneID)
3. Создается/обновляется запись в Firestore
4. Сохраняется состояние в `FirestoreAuthProvider`
5. Пользователь перенаправляется в приложение

## 🔧 Как добавить новый метод аутентификации

### Шаг 1: Добавить экран входа
Создать файл в `lib/screens/auth/` по аналогии с существующими экранами.

### Шаг 2: Добавить сервис
Создать сервис в `lib/services/` для работы с новым методом аутентификации.

### Шаг 3: Интегрировать с FirestoreAuthProvider
Добавить метод в `lib/providers/firestore_auth_provider.dart`:
```dart
Future<void> loginWithNewMethod(...) async {
  // Логика аутентификации
  // Создание/обновление пользователя в Firestore
  // Обновление состояния
}
```

### Шаг 4: Добавить маршрут
Добавить маршрут в `lib/utils/app_router.dart`:
```dart
GoRoute(
  path: '/auth/new-method',
  builder: (context, state) => const NewMethodAuthScreen(),
),
```

### Шаг 5: Добавить кнопку входа
Добавить кнопку в `lib/screens/auth/beautiful_login_screen.dart` или создать отдельный экран выбора метода.

---

## 📝 Примечания

- Все методы аутентификации должны создавать/обновлять пользователя в Firestore
- После успешной аутентификации пользователь должен быть сохранен в `FirestoreAuthProvider`
- Для безопасности токены должны храниться в `flutter_secure_storage`
- Рекомендуется использовать Firebase Auth для всех методов (кроме OneID)
