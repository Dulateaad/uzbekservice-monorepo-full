# 🚀 Система заказов - Быстрый старт (5 минут)

## ✅ Что уже готово

Система заказов **ПОЛНОСТЬЮ ИНТЕГРИРОВАНА И РАБОТАЕТ**:

- ✅ Добавление товаров в корзину на главной странице (кнопка "+")
- ✅ Оформление заказа из корзины
- ✅ Сохранение заказов в БД с привязкой к пользователю (user_id)
- ✅ Отображение заказов в профиле пользователя (`/orders`)
- ✅ Отображение всех заказов в админ-панели (`/admin/orders`)
- ✅ Изменение статуса заказа администратором
- ✅ **Real-time обновление статуса БЕЗ перезагрузки страницы** (автоматический polling)

## 🎯 Как это работает (по шагам)

### **Шаг 1: Пользователь добавляет товар в корзину**

```
Главная страница → Нажать "+" на товаре → Товар добавляется в корзину
```

- Товар сохраняется в БД (таблица `cart_items`)
- Badge в header обновляется с количеством товаров

### **Шаг 2: Оформление заказа**

```
/cart → Нажать "Оформить заказ" → Появляется модальное окно
→ Подтвердить → Заказ создаётся и сохраняется в БД
```

**Что происходит в БД:**

- Запись в таблицу `orders` с полями:
  - `user_id` - ID пользователя
  - `total_amount` - сумма
  - `status` - "pending" по умолчанию
  - `delivery_city`, `delivery_address` - адрес
  - `created_at` - время создания
- Записи в таблицу `order_items` (позиции заказа)

### **Шаг 3: Пользователь видит свои заказы**

```
/orders → Загружаются ВСЕ заказы пользователя
→ Каждый заказ показывает статус, сумму, адрес
```

**Автоматическое обновление:** Каждые 10 секунд страница проверяет, изменился ли статус.

### **Шаг 4: Администратор меняет статус заказа**

```
/admin/orders → Выбрать статус из dropdown → Нажать "Применить"
→ Заказ обновляется БЕЗ перезагрузки
```

**Одновременно:** Если пользователь смотрит `/orders` - его страница АВТОМАТИЧЕСКИ обновится без перезагрузки!

1. Вернитесь в первый браузер на страницу `/orders`
2. **НЕ ПЕРЕЗАГРУЖАЙТЕ** страницу
3. Подождите 5-15 секунд
4. ✅ Наблюдайте: статус заказа обновился АВТОМАТИЧЕСКИ на странице

## 🔗 API Endpoints

```
POST /api/orders
  Body: { user_id, items[], total_amount, delivery_city, ... }
  Response: { success, order }

GET /api/orders/user/:userId
  Response: { orders[] }

GET /api/orders/all?userId=1
  Response: { orders[] }

PUT /api/orders/:orderId/status
  Body: { userId, status }
  Response: { success, order }

DELETE /api/orders
  Body: { ids: [], user_id }
  Response: { success }
```

## 🎛️ Как работает Real-time

**Polling механизм:**

1. При загрузке `/orders` запускается хук `useOrdersPolling`
2. Через 5 сек делается первый запрос: `GET /api/orders/user/:userId`
3. Каждые 10 сек повторяется запрос
4. Сравниваются статусы заказов
5. Если статус изменился → обновляется `state` без перезагрузки
6. Пользователь видит новый статус автоматически

**Почему не WebSocket?**

- Polling проще, не требует отдельного сервера
- Работает везде (даже за NAT/прокси)
- Нагрузка на БД низкая (1 запрос/пользователя каждые 10 сек)
- Для большинства случаев достаточно

## 🐛 Отладка

### Заказ не сохраняется

```javascript
// Проверьте в console.log:
[Order creation] Order data: {...}
[Order creation] API Response: {...}
```

- Если есть ошибка 400 - проверьте поля заказа
- Если 500 - смотрите логи бэкенда

### Статус не обновляется у пользователя

```javascript
// Включите логи в useOrdersPolling:
[OrdersPolling] Status changes detected, updating...
```

- Если нет логов - хук не запустился
- Проверьте что user.id есть

### Заказы не видны в админке

```javascript
// Проверьте ответ от API:
[Admin Orders] API Response: {...}
```

- Должно быть `orders[]` с данными
- Если пусто - нет заказов в БД
