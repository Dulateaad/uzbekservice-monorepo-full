# Техническая спецификация: ESP32 → Firebase Realtime Database (Anama)

Документ для инженера прошивки и для фронтенда: **единый контракт полей**, без необходимости «отправлять код ИИ».

## Хост и путь

- **Проект Firebase:** `anama-app`
- **Realtime Database URL (пример):** `https://anama-app-default-rtdb.firebaseio.com`
- **Путь телеметрии:** `/users/{deviceId}/telemetry`
- **`deviceId`:** строка латиница, цифры, `_`, `-` (например `child_01`). Должна совпадать с ID, который вводит оператор на веб-экране пилота.

## Объект `telemetry` (обновление целиком или по полям)

Поля, которые ожидает веб и серверная функция:

| Поле | Тип | Описание |
|------|-----|----------|
| `bpm` | number | Средний или текущий пульс (уд/мин), после вашей фильтрации |
| `last_rr` | number | Интервал между **двумя последними** ударами, **миллисекунды** |
| `status` | string | `online` \| `offline` |
| `timestamp` | number | Время события: **Unix-секунды** (рекомендуется NTP на ESP). `millis()` с включения платы — не календарное время и плохо для графиков «по дням». |

Пример JSON:

```json
{
  "bpm": 78,
  "last_rr": 769,
  "status": "online",
  "timestamp": 1709467962
}
```

## RR для RMSSD (важно)

Для расчёта **RMSSD** на сервере нужно **20–30 последовательных RR-интервалов**. Одного `last_rr`, обновляемого раз в 2 секунды, **недостаточно**.

Рекомендуется дополнительно писать массив (или скользящее окно) по пути:

- **`/users/{deviceId}/rr_history`** — массив чисел (мс), не более ~30 элементов (старые удалять на устройстве).

Альтернатива: писать каждый валидный интервал в `/users/{deviceId}/rr_log/{pushId}` (тогда на бэкенде нужна агрегация; для пилота проще `rr_history`).

## Поведение без пальца / офлайн

- Обновлять `status: "offline"`, `bpm: 0` с разумным интервалом (как в вашем скетче).
- Не слать заведомо ложные `last_rr`.

## Безопасность (пилот → прод)

Текущие правила в репозитории для пилота открыты для быстрой стыковки с ESP32. Перед продакшеном: **App Check**, отдельный секрет устройства или запись телеметрии **только через HTTPS-функцию**.

## Связь с прошивкой

В скетче используются вызовы вида `json.set("last_rr", rr_interval)` — имена полей должны совпадать с таблицей выше.
