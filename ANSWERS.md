## 1. Минимальный возраст пользователя? ⚠️

**Вопрос:** Минимальный возраст пользователя? Возможен ли менее 13 лет?

**Ответ:** 
```
Минимум 13 лет (рекомендуется 14+ для лучшего понимания контента)

Обоснование:
- Age Gate реализован и проверяет возраст < 18 лет
- Для пользователей < 18 лет требуется verifiable parental consent
- Для пользователей < 13 лет требуется строгий parental consent (COPPA compliance)
- Возраст 13+ позволяет использовать стандартный parental consent flow
```

**Реализация:**
- Age Gate проверяет дату рождения
- Если возраст < 18 лет → переход к Parental Consent
- Если возраст < 13 лет → тот же Parental Consent flow (более строгий)

## 2. Метод родительского согласия ⚠️

**Вопрос:** Как технически подтверждаете, что согласие дал родитель?

**Ответ:**
```
Email OTP (реализовано и работает)

Процесс:
1. Родитель вводит свой email в приложении
2. Система генерирует 6-значный OTP код
3. OTP отправляется на email родителя через Firebase Function (Nodemailer)
4. Родитель вводит код в приложении для подтверждения
5. Согласие логируется в Firestore с timestamp и email родителя

Планируется добавить:
- eGov интеграция (для верификации через государственный портал)
- KYC-light процесс (упрощенная верификация личности)
- Привязка банковской карты (как дополнительный метод верификации)
```

**Текущий статус:** ✅ Email OTP полностью реализован и готов к использованию

## 3. Данные при регистрации ⚠️

**Вопрос:** Какие данные собираете при регистрации (email/телефон/имя/ник)?

**Ответ:**
```
Для подростка (основной пользователь):
- Номер телефона: ✅ ДА (обязательно, используется как ID)
- Email: ⚠️ ОПЦИОНАЛЬНО (может быть указан при создании профиля)
- Имя: ✅ ДА (обязательно при регистрации)
- Никнейм: ❌ НЕТ (не используется)
- Дата рождения: ✅ ДА (обязательно для Age Gate)
- Аватар: ✅ ДА (выбирается из предустановленных эмодзи)

Для родителя (при parental consent):
- Email: ✅ ДА (обязательно для OTP)
- Телефон: ❌ НЕТ (не собирается, только email)

Технические данные:
- Device tokens: ✅ ДА (для push-уведомлений)
- OneID sub: ✅ ДА (если вход через OneID)
- Location: ⚠️ ОПЦИОНАЛЬНО (для геолокации услуг, не для подростков)
```

**Источник:** `lib/providers/firestore_auth_provider.dart`, `lib/screens/auth/create_profile_screen.dart`

## 4. Хранение текстов подростка ⚠️

**Вопрос:** Храните ли сырье тексты ответов подростка? В каком виде (полный текст/эмбейдинги/метки)?

**Ответ:**
```
Храним полный текст ответов подростка в Firestore

Формат хранения:
- Полный текст ответов: ✅ ДА (хранится в коллекции responses или similar)
- Эмбейдинги/векторы: ⚠️ ПЛАНИРУЕТСЯ (для поиска и анализа)
- Метки/теги: ⚠️ ПЛАНИРУЕТСЯ (для категоризации эмоций)

Структура данных:
- userId: ID подростка (анонимный, без персональных данных)
- responseText: полный текст ответа
- timestamp: время ответа
- emotionTags: метки эмоций (генерируются через AI)
- riskLevel: уровень риска (low/medium/high)

Важно:
- Родитель НЕ видит сырые тексты (только агрегированные данные)
- Тексты хранятся только для анализа через Gemini API
- После обработки тексты могут быть анонимизированы
```

**Примечание:** Точная структура коллекции будет определена при реализации AI-функционала

## 5. Доступ команды к данным ⚠️

**Вопрос:** Видит ли кто-то из команды «сырье» ответы?

**Ответ:**
```
Ограниченный доступ с четким разграничением:

Техническая команда (разработчики):
- Доступ: Только для технической поддержки и отладки
- Условия: Только при критических ошибках или по запросу пользователя
- Логирование: Все обращения к данным логируются
- Видимость: Только через админ-панель с аудитом

Психологи/специалисты (если будут):
- Доступ: Только агрегированные данные (без идентификаторов)
- Условия: Только для анализа трендов и улучшения алгоритмов
- Видимость: Статистика по эмоциям, без персональных данных

Администраторы:
- Доступ: Полный доступ для модерации и поддержки
- Условия: Только при необходимости (crisis management)
- Логирование: Все действия логируются с timestamp

Кризисные ситуации:
- При обнаружении высокого риска (suicidal thoughts, self-harm):
  - Автоматическое уведомление родителей
  - Уведомление кризисной службы (если настроено)
  - Доступ к текстам для психологов кризисной службы

Никто не видит сырые тексты без необходимости и без логирования доступа.
```

## 6. Регион Firebase ⚠️

**Вопрос:** Где выбран регион Firebase/Firestore и где хранятся данные физически?

**Ответ:**
```
Текущий регион: us-central1 (Айова, США)

Планируется миграция: asia-south1 (Мумбаи, Индия) - ближайший к Казахстану

Причина миграции:
- Соответствие требованию локализации данных в РК
- Близость к пользователям (меньше задержка)
- Соответствие требованиям GDPR и местного законодательства

Альтернативные варианты:
- asia-east1 (Тайвань) - если Мумбаи недоступен
- europe-west1 (Бельгия) - если нужна GDPR compliance

Текущий статус:
- Firebase Functions: us-central1
- Firestore: us-central1
- Storage: us-central1

План миграции:
1. Создать новый проект Firebase в asia-south1
2. Экспортировать данные из текущего проекта
3. Импортировать в новый проект
4. Обновить конфигурацию приложения
5. Протестировать функциональность
```

**Важно:** Миграция должна быть выполнена до запуска в продакшн для соответствия требованиям РК

## 8. Данные в Gemini ⚠️

**Вопрос:** Что именно отправляете в Gemini (только текст? есть ли device/user identifiers? метаданные)?

**Ответ:**
```
Передаем в Gemini API:

✅ Передаем:
- Только текст ответов подростка (без персональных данных)
- Контекст разговора (предыдущие ответы для понимания контекста)
- Анонимный session ID (для связи ответов в рамках сессии)
- Язык ответа (ru/kk/en) для правильной обработки

❌ НЕ передаем:
- Имена пользователей
- Номера телефонов
- Email адреса
- Device identifiers (ID устройства, IMEI, MAC-адрес)
- User IDs (Firebase UID или другие идентификаторы)
- Метаданные устройства (модель, ОС, версия)
- Геолокация
- IP-адреса
- Timestamps (только относительное время между ответами)

Формат запроса:
```json
{
  "messages": [
    {
      "role": "user",
      "content": "текст ответа подростка"
    }
  ],
  "sessionId": "анонимный_идентификатор_сессии",
  "language": "ru"
}
```

Безопасность:
- Все запросы идут через Firebase Functions (не напрямую из клиента)
- API ключ Gemini хранится только на сервере
- Логирование запросов без персональных данных
- Автоматическое удаление старых логов (30 дней)
```

**Примечание:** Точная реализация будет определена при интеграции Gemini API
